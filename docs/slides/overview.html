Spira Universal Reporter

Automated Test Results to Spira

From any CI/CD pipeline, any test framework, zero test code changes

Dermot Canniffe — Solutions Engineering

The Problem

Customers run automated tests in CI/CD pipelines.

Test results live in pipeline logs, Allure reports, JUnit XML files, or ExtentReports HTML.

None of this data reaches Spira.

Manual entry is not an option at scale. Customers need automated test execution history, evidence, and traceability in Spira — without modifying their test frameworks.

What We Built

A single CLI command that:

  • Parses test results from any supported format
  • Matches tests to Spira test cases automatically
  • Creates test runs with full execution details
  • Uploads evidence (screenshots, videos, logs)

pip install spira-test-reporter
spira-report ./test-results/

Stateless Test Case Matching

No mapping files. No test code changes. Spira is the source of truth.

StepWhat Happens
1Extract stable ID from test result (Allure hash, JUnit classname, test name)
2Search Spira for TC with matching custom property
3aFound → reuse that TC for the test run
3bNot found → auto-create TC, store the ID in custom property
4Next run finds the same TC automatically

Fully stateless — tool is cloned fresh each pipeline run

Zero Friction for the Customer

The customer changes nothing in their test code.

They add two lines to their CI/CD pipeline:


send_to_spira:
  stage: report
  when: always
  script:
    - pip install spira-test-reporter
    - spira-report

Spira credentials from CI/CD environment variables.
Shared config at the group level — each project only needs 3 vars.

What Lands in Spira

  • Test Cases — auto-created with automation ID in custom property
  • Test Runs — pass/fail status, timestamps, duration, errors, stack traces
  • Evidence — screenshots, videos, logs attached to test runs
  • Execution History — builds up over time, same TC reused across runs
  • Release Association — test runs linked to the configured release

In Production

Customer: Large financial services organisation

Frameworks: Selenium/TestNG (ExtentReports) + Cypress (Allure)

Pipeline: GitLab CI/CD

Result: Automated test results flowing to Spira from both frameworks, with screenshots and evidence, zero changes to their test code.

Architecture

  • Python 3.9+ — pip-installable package
  • Pluggable parser registry — new formats via subclass + register
  • Spira REST API v7 — auth, TC search/create, test runs, evidence upload
  • Exponential backoff on rate limiting
  • OS certificate store support for corporate SSL
  • 102 BDD scenarios, 418 steps — offline + live integration tests

Open source, git-maintained, fully documented
