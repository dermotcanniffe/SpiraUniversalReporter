Stateless TC Matching

  • Extract stable ID from test result
  • Search Spira by custom property
  • Found → reuse existing TC
  • Not found → auto-create TC

Spira = Source of Truth

No mapping files. No test code changes. No local state. Fully stateless.

The tool extracts a stable identifier from each test result — Allure content hash, JUnit classname.name, or ExtentReports test name. It searches Spira for a TC with that ID in a custom property. If found, reuses it. If not, creates it. Next run finds the same TC automatically.

What Lands in Spira

  • Test Cases — auto-created with automation ID
  • Test Runs — pass/fail, timestamps, errors, stack traces
  • Evidence — screenshots, videos, logs as attachments
  • Execution History — same TC reused across pipeline runs
  • Release Traceability — runs linked to configured release
